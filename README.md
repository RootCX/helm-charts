# RootCX Helm Chart

Run RootCX on Kubernetes or OpenShift with one chart.

It installs Portal, Core and PostgreSQL as separate workloads, configures OIDC
between Portal and Core, and exposes both over HTTPS.

```bash
helm repo add rootcx https://rootcx.github.io/helm-charts
helm repo update
```

## OpenShift Local

The tested local setup uses OpenShift Local, its `*.apps-crc.testing` domain and
a certificate generated by [mkcert](https://github.com/FiloSottile/mkcert).

```text
Portal  https://portal.rootcx.apps-crc.testing
API     https://api.rootcx.apps-crc.testing
```

### 1. Install mkcert

```bash
# macOS
brew install mkcert

# Windows
choco install mkcert
```

For Scoop and Linux, use the
[official mkcert installation guide](https://github.com/FiloSottile/mkcert#installation).

### 2. Create the local environment

```bash
kubectl config use-context crc-admin
kubectl create namespace rootcx

mkcert -install
mkcert -cert-file rootcx-local.crt -key-file rootcx-local.key portal.rootcx.apps-crc.testing api.rootcx.apps-crc.testing

kubectl create secret tls rootcx-local-tls --namespace rootcx --cert=rootcx-local.crt --key=rootcx-local.key
```

Give Core the public mkcert CA.

macOS, Linux, WSL or Git Bash:

```bash
kubectl create configmap rootcx-local-ca --namespace rootcx --from-file=ca-bundle.crt="$(mkcert -CAROOT)/rootCA.pem"
```

Windows PowerShell:

```powershell
$ca = mkcert -CAROOT
kubectl create configmap rootcx-local-ca --namespace rootcx "--from-file=ca-bundle.crt=$ca/rootCA.pem"
```

Only `rootCA.pem` enters the cluster. Never copy or share `rootCA-key.pem`.

### 3. Create `values.yaml`

```yaml
global:
  platform: openshift
  rootcx:
    hosts:
      portal: portal.rootcx.apps-crc.testing
      core: api.rootcx.apps-crc.testing
    tls:
      secretName: rootcx-local-tls

core:
  trustedCA: rootcx-local-ca
  networkPolicy:
    enabled: false
```

The local profile disables the Core NetworkPolicy because CRC Routes resolve to
a private VM address. Production keeps it enabled.

### 4. Install

```bash
helm install rootcx rootcx/rootcx \
  --namespace rootcx \
  --values values.yaml \
  --wait \
  --timeout 10m

kubectl get pods --namespace rootcx
helm test rootcx --namespace rootcx --logs
```

Open [https://portal.rootcx.apps-crc.testing](https://portal.rootcx.apps-crc.testing)
and register `admin@rootcx.localhost`.

If the browser was open during `mkcert -install`, restart it. Remove the local
CA later with `mkcert -uninstall`.

## Production

Requirements:

- Kubernetes 1.28+ or OpenShift;
- Helm 3.14+;
- two DNS names pointing to the ingress controller or OpenShift router, for
  example `portal.example.com` and `api.example.com`;
- a trusted certificate covering both names, such as `*.example.com`;
- a default `ReadWriteOnce` StorageClass when using embedded PostgreSQL.

Start with the example for your platform:

- [Kubernetes values](examples/values-kubernetes.yaml)
- [OpenShift values](examples/values-openshift.yaml)

Replace every `REPLACE_WITH_...` value. Production mode rejects incomplete
security configuration.

### TLS

For Kubernetes Ingress, create the Secret named by
`global.rootcx.tls.secretName` with the certificate chain and matching private
key:

```bash
kubectl create namespace rootcx
kubectl create secret tls rootcx-tls --namespace rootcx --cert=fullchain.pem --key=privkey.pem
```

For OpenShift, you can use the router's default wildcard certificate by leaving
`global.rootcx.tls.secretName` empty, provided it covers both Route hosts and is
trusted by clients.

To use your own wildcard certificate, first verify that the cluster supports
externally managed Route certificates:

```bash
kubectl explain route.spec.tls.externalCertificate
```

Then create the Secret named by `global.rootcx.tls.secretName`:

```bash
kubectl create namespace rootcx
kubectl create secret tls rootcx-tls --namespace rootcx --cert=server.crt --key=server.key
```

The chart gives the OpenShift router read-only access to that Secret. Follow the
certificate format documented by your cluster's `kubectl explain` output.

Have the platform certificate manager renew the certificate in the same Secret.
The chart references the Secret; it does not issue or renew certificates.

With a private enterprise CA, browsers and workloads must trust that CA. Give
its public chain to Core when Core connects to endpoints signed by it:

```bash
kubectl create configmap rootcx-enterprise-ca --namespace rootcx --from-file=ca-bundle.crt=enterprise-ca-chain.pem
```

```yaml
core:
  trustedCA: rootcx-enterprise-ca
```

Leave `core.trustedCA` empty for certificates issued by a CA already trusted by
the container.

### Install

Generate the OIDC signing key:

```bash
openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:2048 -out oidc-private-key.pem
chmod 600 oidc-private-key.pem
```

Install with your completed `values.yaml`:

```bash
helm upgrade --install rootcx rootcx/rootcx \
  --namespace rootcx \
  --create-namespace \
  --values values.yaml \
  --set-file oidc.signingKey=oidc-private-key.pem \
  --wait \
  --timeout 10m

helm test rootcx --namespace rootcx --logs
```

Use an existing Kubernetes Secret or the organization's external secret
operator in production. Do not commit credentials or private keys.

SMTP is optional. Embedded PostgreSQL is suitable for local and single-node
installations; use an externally operated PostgreSQL service when production
requires high availability, managed backups or point-in-time recovery.

Private endpoints blocked by the default NetworkPolicy must be added explicitly
under `core.networkPolicy.extraEgress`. Do not use guessed domains or CIDRs.
